# 数据库与 MySQL

## 索引原理
MySQL InnoDB 用 B+ 树组织索引：非叶子节点只存键，叶子节点存完整数据（聚簇索引）并按序连接，天然支持范围查询。索引能大幅加速查询，但会拖慢写入，且占用空间，不能乱建。

## 为什么用 B+ 树不用哈希或二叉树
哈希只支持等值查询不支持范围；二叉树层数随数据量增长（退化成链表更糟）；B+ 树扇出大、层数低（千万级数据 3-4 层），且叶子有序适合范围查询和磁盘顺序 IO。

## 事务 ACID
原子性（A）：要么全做要么全不做；一致性（C）：事务前后数据满足约束；隔离性（I）：并发事务互不干扰；持久性（D）：提交后不丢失。InnoDB 通过 undo log 保证原子性、redo log 保证持久性。

## 隔离级别
读未提交、读已提交、可重复读（MySQL 默认）、串行化。可重复读通过 MVCC 实现：每行带版本号，读快照，避免幻读还需间隙锁。

## 慢查询优化
先 EXPLAIN 看执行计划（type、key、rows），常见手段：给 WHERE/JOIN/ORDER BY 字段加索引、避免 SELECT *、避免函数包裹索引列、小表驱动大表、分页深翻页用覆盖索引或游标。

## 索引失效场景
对索引列做函数运算、隐式类型转换、like '%xx' 前置通配符、联合索引不满足最左前缀、OR 连接非索引列。

## 主从复制与读写分离
主库写 binlog，从库拉取并回放实现异步复制；读写分离缓解主库压力，但存在复制延迟，读敏感业务要特殊处理。

## 乐观锁与悲观锁
悲观锁：SELECT ... FOR UPDATE 直接加锁；乐观锁：版本号或 CAS，更新时校验 version，失败重试。高并发下乐观锁更合适。

## 索引类型
主键索引（聚簇）、唯一索引、普通索引、联合索引、全文索引；覆盖索引指索引中包含查询所需全部字段、免回表。联合索引遵循最左前缀：a,b,c 索引能命中 a、a,b、a,b,c，跳列就失效。

## MVCC 原理
每行记录带隐藏字段：事务 id 与回滚指针；读操作基于版本链构造快照（ReadView）。读已提交每次读生成新快照；可重复读事务内复用同一快照，但当前读（for update）仍需间隙锁防幻读。

## Redis 缓存三兄弟
缓存穿透：查询不存在的数据绕过缓存打 DB → 布隆过滤器或缓存空值；缓存击穿：热点 key 过期瞬间高并发打 DB → 互斥锁或热点 key 不过期；缓存雪崩：大量 key 同时过期 → 过期时间加随机值、集群高可用、限流降级。

## 分库分表
单表数据量大时水平分片（按 id 取模/范围）或按业务域垂直拆分；代价是跨库 join、分布式事务、全局唯一 id（雪花算法）。小数据量不要提前分库分表，先优化索引与缓存。

## 幂等设计
重复请求不产生重复副作用：唯一业务号约束、状态机校验、Redis SETNX 分布式锁 + 幂等表；支付回调尤其要做幂等，用业务号做唯一键。

## 数据库连接池
复用连接避免频繁握手，限制并发保护 DB；SQLAlchemy 等框架默认带连接池，注意用完归还连接（不泄漏）与池大小设置——不是越大越好。

## SQL 注入与防御
把用户输入直接拼进 SQL 就会注入；用参数化查询（prepared statement）或 ORM，禁止字符串拼接；配合输入校验、最小权限账号与敏感 SQL 审计。

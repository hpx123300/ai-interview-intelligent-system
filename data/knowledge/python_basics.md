# Python 基础与进阶

## GIL 全局解释器锁
Python 的 GIL 让同一时刻只有一个线程执行字节码，导致多线程无法利用多核跑 CPU 密集型任务。IO 密集型任务会主动释放 GIL，所以多线程适合 IO 场景；CPU 密集型用多进程（ProcessPool）或协程。

## 装饰器
装饰器是接收函数并返回新函数的可调用对象，用于在不改原函数的情况下增强行为（日志、鉴权、计时）。原理是闭包：外层函数接收函数，内层函数包装并调用它。用 functools.wraps 保留原函数元信息。

## 生成器与迭代器
迭代器实现 __iter__ 和 __next__；生成器用 yield 惰性产出值，一次只占一个值的内存，适合大数据流。yield from 用于委托子生成器。

## 深浅拷贝
浅拷贝（copy.copy）只复制外层容器，内层对象仍共享引用；深拷贝（copy.deepcopy）递归复制所有层。修改浅拷贝的内层可变对象会影响到原对象。

## 可变与不可变对象
不可变：int、str、tuple、frozenset；可变：list、dict、set。函数默认参数不要用可变对象，否则多次调用会共享状态（经典坑：def f(a=[])）。

## 列表与字典底层
list 是动态数组，尾部 O(1)、中间插入 O(n)；dict 是哈希表，查找平均 O(1)，键必须可哈希。

## 上下文管理器
with 语句通过 __enter__ / __exit__ 管理资源，保证异常时也释放（文件、锁、数据库连接）。也可以用 contextlib.contextmanager 装饰器实现。

## 闭包与作用域
函数可以捕获外层变量形成闭包。局部变量、nonlocal、global 的作用域规则要清楚：内层函数修改外层变量需要 nonlocal。

## 垃圾回收
CPython 用引用计数为主 + 分代回收处理循环引用。del 只是减少引用计数，不是立刻释放内存。

## 类型注解
Python 3.10+ 支持 | 联合类型和类型别名；配合 mypy 做静态检查。运行时用 typing 或 pydantic 做校验。

## 面向对象三大特性
封装：把数据和行为打包成类，对外暴露最小接口；继承：子类复用并扩展父类，注意多继承的 MRO（C3 线性化）；多态：同一接口不同实现，鸭子类型就是运行时按行为而非类型判断。

## 类变量与实例变量
类变量定义在类体里，所有实例共享；实例变量通过 self 赋值，各实例独立。直接 `实例.类变量 = 值` 会创建同名实例变量遮蔽类变量，修改类变量要用类名访问。

## __init__ 与 __new__
`__new__` 在创建实例前被调用并返回实例，`__init__` 负责初始化；单例模式通常重写 `__new__` 控制实例个数。`__slots__` 可限制实例属性并减少内存占用，适合大量实例场景。

## 多线程、多进程与协程怎么选
IO 密集型：协程或线程（asyncio / ThreadPoolExecutor），等待 IO 时让出 CPU；CPU 密集型：多进程（ProcessPoolExecutor）绕过 GIL；两者都有：多进程 + 进程内协程。爬虫、HTTP 服务、数据库访问基本都是 IO 密集。

## asyncio 原理
基于事件循环 + 协程 + select/epoll：`await` 挂起当前协程，事件循环在 IO 就绪时恢复它。`async def` 是协程函数，`await` 只能出现在协程内；`asyncio.gather` 并发执行多个协程。不要在事件循环里跑 CPU 密集任务。

## 异常处理
try/except/finally 捕获异常，except 按类型匹配，多异常用元组；用 Exception 兜底但不要裸 except 吞掉所有异常；finally 保证清理；自定义异常继承 Exception，`raise from` 保留异常链方便排查。

## 数据模型与魔法方法
`__str__` 面向用户、`__repr__` 面向开发者；`__eq__`/`__hash__` 要一起覆写（可变对象不要做 dict 键）；`__getitem__`/`__len__` 让对象可迭代；with 依赖 `__enter__`/`__exit__`。

## 性能优化思路
先用 profile 定位热点再优化；常见手段：局部变量、列表推导/生成器、缓存（functools.lru_cache）、避免不必要拷贝、N+1 查询改批量、字符串拼接用 join、CPU 密集用多进程或 C 扩展。

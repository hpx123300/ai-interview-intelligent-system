# AI 与大模型应用

## LLM 基本原理
大语言模型基于 Transformer，预测下一个 token；训练分预训练（海量文本学习语言规律）和对齐（SFT + RLHF 让输出符合人类偏好）。模型本身没有数据库，知识来自训练数据，所以有幻觉和时效问题。

## Function Calling 是什么
把工具函数以 JSON Schema 声明给模型，模型决定"该调用哪个函数、传什么参数"，应用侧执行后把结果回填给模型，模型再组织回答。这是 Agent 与外部世界交互的基础：结构化输出、可校验、可审计。

## RAG 检索增强生成
流程：文档切块 → 向量化（embedding）→ 存入向量库 → 用户提问时检索最相关片段 → 拼进提示词 → 模型基于原文回答。作用：缓解幻觉、支持私有/最新知识、可溯源。评估常用 Recall@K、MRR。

## Agent 是什么
Agent = LLM 决策 + 工具调用 + 记忆 + 规划，在循环里"思考→行动→观察"直到完成任务。单 Agent 适合任务简单；多 Agent 把一个复杂任务拆给多个角色（如主管路由 + 专员执行），职责分离、可扩展。

## Prompt 工程
核心技巧：明确角色与目标、给出格式约束与示例（few-shot）、拆解复杂指令、要求逐步思考（CoT）。输出可靠性靠 JSON mode + 严格校验，而不是只靠提示词。

## 幻觉与缓解
模型可能编造不存在的事实。缓解手段：RAG 提供原文依据、让模型"不知道就说不知道"、输出带引用、增加校验与兜底。

## Token 与上下文窗口
模型输入输出按 token 计费；上下文窗口有限，超长要截断/摘要/检索。控制成本常用缓存、限流、压缩历史。

## 生成参数怎么调
temperature 控制随机性（抽取/分类用 0.1-0.3，创意写作可调高）；top_p 核采样；max_tokens 限制输出长度；stop 提前终止。结构化输出用 response_format=json_object + 严格校验兜底。

## Function Calling 工程要点
参数必须可 JSON 序列化；工具描述要写清楚"什么时候用、参数含义"；执行端做参数校验、超时与异常兜底；工具结果按 tool_call_id 回填完整；同一轮可并行多个工具调用。测试要覆盖"选错工具、参数非法、工具报错"三类异常。

## RAG 是什么
流程：文档切块 → 向量化（embedding）→ 存入向量库 → 用户提问时检索最相关片段 → 拼进提示词 → 模型基于原文回答。作用：缓解幻觉、支持私有/最新知识、可溯源。评估常用 Recall@K、MRR、忠实度。

## 切块策略
按标题/章节切块保留语义上下文，块大小与重叠要调优：太小丢上下文、太大噪声多；常见 200-800 token + 10%-15% 重叠；结构化文档优先按 Markdown 标题切，检索单元与生成单元可分离（parent-child）。

## Embedding 与向量库
embedding 把文本映射为稠密向量，语义相近则距离近；向量库（FAISS/Milvus/pgvector）做 ANN 近似最近邻检索。中文场景可用 bge/m3e 等中文向量模型；检索时 query 与 chunk 用同一模型编码，embedding 模型要复用缓存，避免每次查询重复加载。

## 混合检索与 RRF
关键词检索（BM25/jieba）擅长精确匹配（专有名词、编号），向量检索擅长语义召回；二者用 Reciprocal Rank Fusion 融合：score = Σ 1/(k + rank)，两路都命中的排前面。实践上比单路检索稳定，还能缓解新词、错别字的召回失败。

## 检索质量怎么评估
构造带标准答案的评测集（query → 期望片段）；Recall@K 看 top-K 是否召回正确答案，MRR 看正确答案的名次；再结合端到端问答准确率与引用忠实度。分块与检索参数调整要有指标支撑。

## Agent 是什么
Agent = LLM 决策 + 工具调用 + 记忆 + 规划，在循环里"思考→行动→观察"（ReAct）直到完成任务。关键设计：什么时候该调用工具、工具失败怎么恢复、迭代上限、过程可追踪可审计。

## ReAct 模式
Reason + Act：先推理需要什么信息 → 调用工具 → 观察结果 → 再推理，循环至完成。实现上用 Function Calling 承载工具调用，提示词约束步骤，设置最大迭代次数防止死循环，超限给兜底回复。

## 多 Agent 架构
单 Agent 适合简单任务；多 Agent 把复杂任务拆给多个角色（主管路由 + 专员执行），职责分离、提示词更聚焦、可扩展。代价：更多 LLM 调用、延迟与成本上升，还要处理路由错误与上下文同步。判断标准是任务是否真的需要分工。

## 记忆设计
短期记忆 = 会话上下文（注意窗口裁剪）；长期记忆 = 外部存储（数据库/向量库）按需回填；记忆注入要控制长度与相关性。本项目把 SQLite 历史回填进记忆，刷新页面不丢上下文。

## Agent 失败处理
工具异常捕获后把错误信息回填给模型重新规划；JSON 解析失败用正则兜底提取；迭代超限返回友好提示；网络/API 错误做指数退避重试与降级（关键词检索兜底向量检索、题库兜底 LLM 出题）。

## Prompt 工程
核心技巧：明确角色与目标、给出格式约束与示例（few-shot）、拆解复杂指令、要求逐步思考（CoT）。输出可靠性靠 JSON mode + 严格校验，而不是只靠提示词；写清楚"不要做什么"比堆要求更有效。

## 幻觉与缓解
模型可能编造不存在的事实。缓解手段：RAG 提供原文依据、让模型"不知道就说不知道"、输出带引用、增加校验与兜底；评估上检查忠实度（答案是否都来自引用）。

## 微调 vs RAG
RAG 适合知识更新快、需要溯源、无标注数据的场景；微调适合改变风格/格式/领域能力，成本高且知识易过时。一般先 RAG，遇到风格与能力瓶颈再考虑微调，或两者结合：RAG 供事实、微调管表达。

## 流式输出与体验
流式（stream=True）逐 token 返回，首字延迟低；工具调用轮不产出文本，UI 提示"正在调用工具"；多轮流式要把累积内容正确写回记忆，防止丢消息。

## 大模型应用安全
Prompt 注入：输入里隐藏"忽略系统指令"；缓解：输入校验、系统提示词加固、输出敏感信息过滤、最小权限工具（专员只能看自己的工具子集）、速率限制与审计日志。
